# VeraLane

**Banking, verified.** 面向金融科技竞赛的本地 AI Banking 原型：自然语言形成业务草稿，由确定性工具查询、核验与生成授权快照，用户确认后执行模拟银行操作。

> 当前版本默认 **离线规则模式**。账户、联系人、流水、卡片、产品与商户均为虚构数据。没有连接真实银行、支付通道或商户；模拟验证码不构成真实身份认证。仓库为私有。

## 已交付功能

| 场景 | 可操作流程 |
| --- | --- |
| 转账 | 一句话即时/单次预约、同名消歧、确认保存联系人别名、相似付款提示；有限次数周期转账、批量逐项回执；按明确日期创建可取消的站内转账提醒，到期只提示核对、不执行转账 |
| AA 收款 | 从自然语言或交易明细发起，本人垫付、2–8 人均分/按明确口述份数或合计 100% 的整数百分比预填权重/整数比例/手动份额/按菜品拆分，确认建单、分次/付清模拟回款与逐笔回执；支持按原回款流水授权部分/全额退款；未收单据在 3 个演示日后生成一次站内提醒；多人垫付可保存结算计划并逐笔模拟本人相关转入/转出 |
| 账单 | 自然语言筛选、等长期间比较、异常线索与交易证据；柱状/环形/日趋势图；CSV、JSON、打印/PDF；聊天中可按流水编号、商户/金额或最近唯一查询结果发起分类修正，并在确认后更新统计口径；可设定或调整月度分类/总预算；展示未来资金口径 |
| 订阅 | 周期扣费诊断、协议核实、涨价依据、续费站内提醒、逐项选择并取消代扣；不声称商户会员已退订 |
| 跨场景任务 | 支出优化四步计划、版本化选择与独立授权、逐项结果及目标差额；生日草稿、资金预留、约定时间模拟下单/配送、独立取消订单与退款 |
| 卡片 | 尾号核对、锁定/解锁、线上限制、调低支付限额、强验证挂失、模拟刷卡实际拦截；新卡申请/审批/发卡分离，授信提额转模拟审核 |
| 理财 | 版本化五题测评、虚构产品筛选对比、红级申购/赎回、批次持仓与锁定期、T+1 演示工作日 09:00 结算 |
| 共用控制 | 10 分钟确认、3 分钟操作绑定模拟验证、执行时再核验、幂等、SQLite 事务和审计；预留资金不可挪用；共享业务时钟、模型用量与预算限制 |

本次完成路线图编号 **F01–F09、X01–X09** 的原型实现，并补入周期/批量转账、完整模拟卡申请流程、分类修正与预算。F08 早期联网样本 3/3 因 HTTP 401 规则降级；2026-10-05 另一次获授权的隔离评测中，2/3 请求返回 HTTP 401，1/3 返回可解析的转账意图及 300 元金额，但收款人和备注未能核实。样本不足以估算模型准确率；依用户选择保持默认离线，**不把规则回退计为模型成功**。详见 [模型评测记录](docs/model-evaluation.json)。

按菜品拆分支持手动录入，或用本机 RapidOCR 从 JPEG/PNG/WebP 小票生成菜名和金额候选；图片通过本机回环地址送到本地进程，在内存中识别，不传云端、不落盘。OCR 不自动分配参与人、不改垫付总额、不建收款单；用户须逐项核对后再计算和确认。AA 多人垫付结算计划可确认后保存；经过本人账户的每笔路径都须另行授权并进入本地模拟账本。其他参与人之间的路径只作为待线下处理的建议，不会被标记为已付款。AA 退款是本地模拟账本操作：仅可从已付清份额的原到账流水退款，生成独立支出交易，不撤销原回款或消费，也不自动重开收款单。仍未实现外部自动催收、真实 IM 平台接入、真实身份验证和银行清算；不得宣传为已完成的线上能力。

## 快速启动（Windows）

要求 Python 3.11+、uv、Node.js 20.19+（或 22.12+）、npm。仓库包含 Python 与 npm 锁文件。

```powershell
# 仓库根目录：构建前端、安装后端依赖并启动本地单端口演示
.\scripts\run-demo.ps1
```

脚本仅在 `.env` 不存在时复制 `.env.example`，不会覆盖已有密钥。默认打开 `http://127.0.0.1:8000`；端口已占用时可用 `-Port 8001`。OCR/NumPy 默认限制为 1 个 BLAS 线程以减少本机内存占用；可用 `-BlasThreads 2` 调整（范围 1–16）。脚本不修改系统执行策略；若本机策略不允许脚本，可按下面命令逐步运行。

```powershell
cd frontend
npm ci
npm run build
cd ../backend
uv sync --frozen
uv run --frozen --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端构建产物由 FastAPI 在 API 路由后提供；只公开 `frontend/dist`，不公开项目根目录、数据库或配置。`/docs` 提供自动生成的 API 文档。首次启动创建 `data/veralane.sqlite3`，重启保留全部记录。

首次安装后端依赖会额外下载本地 OCR 推理组件（RapidOCR、ONNX Runtime、OpenCV，合计约 100 MB）；不需要 OCR 云服务或密钥。小票识别本身完全在本机运行。

### 开发模式

```powershell
# 终端一
cd backend
uv sync --frozen --extra test
uv run --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
# 终端二
cd frontend
npm ci
npm run dev
```

浏览器访问 Vite 显示的地址（默认 `http://127.0.0.1:5173`）。`/api` 代理到 8000。页面使用哈希路由，支持刷新与前进/后退：`#/chat`、`#/transfer`、`#/bills`、`#/subscriptions`、`#/tasks`、`#/cards`、`#/investments`。

## 配置与数据

| 配置 | 含义 |
| --- | --- |
| `VERALANE_MODEL_MODE=offline` | 默认且显式离线；只有设为 `auto` 才启用外发模型请求。未设置或填错时均保持离线 |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | 仅在本机 `.env` 设置，不提交仓库；鉴权失败等情况回退规则 |
| `DEEPSEEK_MAX_CALLS` / `DEEPSEEK_MAX_TOTAL_TOKENS` | 持久化调用/令牌上限，失败与不确定请求保守计入 |
| `DEEPSEEK_BUDGET_YUAN` | 配置价格下的估算上限；不是平台账户余额，也不含启用本地账本前的消费 |
| `DEEPSEEK_INPUT_PRICE_PER_MILLION_YUAN` / `DEEPSEEK_OUTPUT_PRICE_PER_MILLION_YUAN` | 两项须配齐才估价；未配不显示零成本。已有未定价历史时补价格会阻止继续调用，避免低估 |
| `VERALANE_DEMO_CONTROLS=0` | 关闭模拟验证码、模拟付款、时间推进、模拟审批/发卡等演示入口；不等于生产安全模式 |
| `VERALANE_DB_PATH` | 可选择独立 SQLite 路径，用于新演示；原数据库不会自动删除 |

原型使用一个共享虚构账户。会话 ID 只隔离任务入口，不是登录认证。当前竞赛演示部署在 `https://demo.wuyeni.cn`，由 Nginx 在公网终止 TLS 并对所有页面/API 执行共享 Basic Auth；应用容器仍只监听服务器 `127.0.0.1:8000`。这只是受口令保护的虚构数据演示入口，不是公网银行服务，不能接真实账户或敏感信息。详见 [部署说明](docs/部署说明.md) 和 [安全自评与权限分级](docs/安全自评与权限分级.md)。

初始业务日期为 `2026-09-30 09:00 +08:00`。业务时钟不会随电脑时间自然流逝；在任务中心“资金预留与时钟”或预约面板显式推进。所有会话共用时钟，推进会处理全局最早到期事件；授权有效期仍按实际 UTC 计算。

如需重新演示，先停止服务，备份数据并将 `VERALANE_DB_PATH` 指向一个新的文件。不要为了演示成功自动清空旧流水。默认账本只带近期流水；如需展示跨年账单趋势，可先停止服务并备份数据库，再显式追加八个月的 32 笔虚构历史流水：

```powershell
cd backend
uv run --frozen --env-file ../.env python -m app.demo_history --database ..\data\veralane.sqlite3 --confirm-fictional-history
```

将 `--database` 改为实际的 `VERALANE_DB_PATH`。该命令只向已初始化的 VeraLane SQLite 数据库追加历史交易，不重算余额；可安全重复运行，第二次起不会重复插入。必须同时提供目标路径和 `--confirm-fictional-history`，程序不会自动加载，也不会清空流水。

## 关键演示流程

1. 账单页问“上个月餐饮花了多少”，打开对应交易；切换图表并导出。
2. 在对话工作台输入“帮我看看上个月为什么花得多，再看看下个月能不能少花300元”，点击回复中的跳转按钮；任务中心打开已保存的账单证据与协议选项，选择后再确认取消。未选择的代扣保持生效，目标不足会显示真实差额。
3. 给“王明”转账展示消歧；给明确联系人生成 1200 元计划，完成模拟强验证，再单独确认。
4. 卡片页锁定尾号 6018，打开模拟刷卡测试，验证后端阻止付款；解锁后恢复正常检查。
5. 完成虚构测评，申购稳享 100 元；赎回后看到“待到账”，推进到下一结算事件才增加可用现金。
6. 建立生日任务，选择虚构商品与配送信息，确认预留；推进到下单、送达节点。任务取消与订单退款分别演示。
7. 转账页“周期 / 批量”核对具体日期或逐笔金额，观察每期状态及部分失败回执；AA 仅在模拟回款后入账。
