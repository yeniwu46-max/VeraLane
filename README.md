# VeraLane

VeraLane 是一个使用自然语言操作**虚构银行账户**的参赛原型。模型负责理解意图；服务端工具读取账本、核对对象和金额、判定权限，并在取得用户确认后执行模拟写操作。界面持续展示账户、交易和审计记录。

## 当前可运行范围

| 场景 | 已实现 |
| --- | --- |
| 智能转账 | 一句话即时/单次预约转账；日期与时间补齐、同名联系人消歧；确认授权；预约持久化、取消、到期执行及回执；重复确认和扫描不重复扣款；也可手动填写即时转账 |
| AA 分账 | 一句话或从支出明细发起；本人垫付、2–8 人均分、余数分配与逐人改额；同名澄清；确认建单；模拟回款、到账回执、进度追踪和关闭剩余请求 |
| 账单分析 | 本月、上月、今年、去年支出分类；分类柱状图、占比环图、交易日趋势；逐笔交易弹窗；CSV、JSON 下载与浏览器打印保存 PDF；透明规则提示高金额交易 |
| 订阅管理 | 从连续两个月的扣费记录识别候选订阅并标记 30 天内续费；查询已保存的模拟代扣协议；确认后取消协议 |

高风险转账会生成计划并被强验证门槛阻止。强验证、周期预约、多人垫付后的债务抵消、基于更长交易历史的稳健周期识别、卡片、理财和跨场景任务仍在后续开发范围。所有业务数据都是虚构的，不连接真实银行或商户。

## 本地启动

需要 Python 3.11+、[uv](https://docs.astral.sh/uv/) 和 Node.js 20.19+。打开两个终端：

```powershell
# 终端一，仓库根目录；已有 .env 时保留本地配置
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 在本地 .env 中设置 DEEPSEEK_API_KEY；留空则使用离线规则解析
cd backend
uv sync --extra test
uv run --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
# 终端二，仓库根目录
cd frontend
npm install
npm run dev
```

浏览器打开 Vite 终端显示的地址（默认 `http://127.0.0.1:5173`，端口被占用时会自动顺延）。前端将 `/api` 代理到本机端口 8000。API 文档位于 `http://127.0.0.1:8000/docs`。先启动后端；SQLite 演示数据首次启动时自动生成到 `data/`。

左侧导航对应独立的 `#/chat`、`#/transfer`、`#/bills`、`#/subscriptions` 页面。转账页可选择已验证联系人并生成确认计划；账单页可切换期间并逐笔查看来源；订阅页可查看协议与扣费证据并发起取消计划。地址可直接打开，浏览器前进/后退和刷新会回到对应页面。

转账页以自然语言输入为主入口，输入“转给林悦 300 元，备注房租”即可得到待确认计划；遇到同名收款人时可选择脱敏手机号对应的联系人。手动表单折叠在下方。账单页可切换三种图表，点击任一交易打开明细；CSV 和 JSON 由后端按当前期间生成，PDF 使用浏览器“打印 / PDF”并应用账单打印样式。

界面采用深海军蓝金融工作台视觉，以冷蓝标记操作、香槟金提示授权确认。对话结果按实际解析方式标记 `AI` 或 `规则`，可展开查看模型、银行工具与模拟数据各自的作用。转账与取消代扣的确认卡列出具体对象和影响，核对勾选后才启用执行按钮；高风险操作仍被服务端强验证边界拦截。

对话工作台默认展开到可用空间，右侧账户概览默认收起，可从右上角按需打开。对话框右下角可拖动调整宽度和高度，也支持方向键微调与“重置大小”；首页展示横幅已移除。

## 演示顺序

1. 输入“我的账户余额是多少”，查看只读操作直接回复。
2. 输入“本月账单”，查看分类、交易数量及高金额复核提示。
3. 在转账页输入“转给王明 200 元，备注聚餐”，展示同名澄清；点选脱敏手机号对应的联系人后核对计划。
4. 在转账页输入“转给林悦 300 元，备注房租”，观察确认前余额不变；确认后余额、交易和审计变化。
5. 打开账单页，切换三种图表、点击交易查看明细，再导出 CSV、JSON 或通过打印保存 PDF。
6. 输入“查看订阅”，再输入“取消云影会员自动续费”，确认后查看协议状态。
7. 输入“转给林悦 1200 元”，展示红色权限拦截。
8. 输入“明天晚上8点给林悦转300元，备注房租”，核对完整日期后点击“确认预约”；刷新页面，“我的预约”仍有待执行记录。展开“演示时间控制”，点击“推进到下一预约时间”，查看执行回执和关联交易编号。也可在执行前打开明细取消预约。
9. 在智能转账页切换“AA 收款”，输入“聚餐我垫了368.50元，我、林悦、王明、陈晨四个人AA”。按脱敏手机号选择王明，核对分摊预览并确认建单；余额保持不变。在单据明细的演示控制中模拟一位参与者付款，查看部分收齐、增加的余额及交易编号。也可从账单交易明细的“AA 分摊”发起。

### AA 分账与模拟回款

- 本人是唯一垫付者，分摊名单必须包含本人和 1–7 位已验证联系人；本人可手动设为承担 0 元。原句仅说“我垫付”时，仍需明确是否包含本人；提到其他人垫付、人数不符或未知联系人时须核对。
- 所有金额使用整数分。默认按“本人在前、联系人按预览顺序”均分，余数依次每人加 1 分；368.50 元四人均分为 92.13、92.13、92.12、92.12 元。手动改额须覆盖全部参与人且合计等于总额，0 元份额不生成付款请求。
- 预览和确认建单均不扣款，也不产生收入。账单发起时金额绑定原支出；自述垫付标记为未关联支出，不补写消费。只有显式模拟付款才生成 `AA回款` 收入交易并增加余额；现有支出报告不冲减原消费。
- 收款单保存授权快照并绑定当前会话；重复确认不会重复建单，同一付款请求重试不会重复入账。原支出已有分摊单时会阻止重复建单；仅完全未到账且已关闭的单据可释放该来源重新发起。
- 可关闭待收款或部分收齐单据，停止剩余请求并保留已到账金额和回执；关闭不会退款。当前每位参与者一次付清份额，暂不支持分期、退款、多垫付人、OCR、自动催收或真实付款链接。
- “模拟付款”由 `VERALANE_DEMO_CONTROLS` 控制；设为 `0` 后关闭模拟入账接口，查询仍可用。本地原型不发送真实消息、不访问付款人的账户，也不执行真实付款。到账时间使用共享演示时钟，确认凭证仍按真实时间在 10 分钟后过期。

### 预约与演示时钟

- 初始演示时间为 `2026-09-30 09:00:00 +08:00`（日期可由 `VERALANE_DEMO_DATE` 在首次初始化前配置）。时间保存在 SQLite 中，重启不会归零，也不会随电脑时间自动流逝；用演示控制推进。
- 即时转账日期、每日限额、账单期间、订阅提醒和预约到期判断使用同一演示时钟。“明天”等表达以页面显示时间为准，确认卡始终显示完整北京时间。裸“8点”、模糊日期、多时间或周期要求会追问。
- 预约授权确认凭证使用**实际时间**，10 分钟后过期；确认后成为独立的持久化预约。创建预约不提前扣款或冻结资金。
- 后端每 2 秒检查到期任务；时间推进接口也立即触发检查。执行窗口为 `[预约时间, 预约时间 + 10分钟)`；关闭后端期间不会执行，恢复后超过窗口则失效、不补扣。余额不足、联系人变化或日累计超限时失败，不自动重试业务。
- 演示控制推进全局时钟至最近的一笔待执行预约，处理所有已授权到期任务；可能包括其他浏览器会话的预约。可在 `.env` 设置 `VERALANE_DEMO_CONTROLS=0` 关闭入口和接口。此控制只适合当前本地虚构账户演示。
- 当前会话可查看或取消其预约；会话 ID 保存在浏览器本地。清除浏览器本地存储会失去原会话入口，但已确认预约仍可能执行；原型尚无登录账户下的跨设备任务管理。

要重置本地演示数据，先停止后端，再删除 `data/veralane.sqlite3`，随后重新启动。删除会清除模拟交易、授权、预约、AA 收款单与回款、审计及演示时钟；需要保留记录时先备份。
