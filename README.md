# VeraLane

**Banking, verified.** 面向金融科技竞赛的本地 AI Banking 原型：自然语言形成业务草稿，由确定性工具查询、核验与生成授权快照，用户确认后执行模拟银行操作。

> 当前版本默认 **离线规则模式**。账户、联系人、流水、卡片、产品与商户均为虚构数据。没有连接真实银行、支付通道或商户；模拟验证码不构成真实身份认证。仓库为私有。

## 已交付功能

| 场景 | 可操作流程 |
| --- | --- |
| 转账 | 一句话即时/单次预约、同名消歧、确认保存联系人别名、相似付款提示；有限次数周期转账、批量逐项回执 |
| AA 收款 | 从自然语言或交易明细发起，本人垫付、2–8 人均分/整数比例/手动份额、确认建单、分次/付清模拟回款与逐笔回执；未收单据在 3 个演示日后生成一次站内提醒；多人多笔垫付可计算净额和建议结算路径 |
| 账单 | 自然语言筛选、等长期间比较、异常线索与交易证据；柱状/环形/日趋势图；CSV、JSON、打印/PDF；保留原始流水的分类修正、月度预算和未来资金口径 |
| 订阅 | 周期扣费诊断、协议核实、涨价依据、续费站内提醒、逐项选择并取消代扣；不声称商户会员已退订 |
| 跨场景任务 | 支出优化四步计划、版本化选择与独立授权、逐项结果及目标差额；生日草稿、资金预留、约定时间模拟下单/配送、独立取消订单与退款 |
| 卡片 | 尾号核对、锁定/解锁、线上限制、调低支付限额、强验证挂失、模拟刷卡实际拦截；新卡申请/审批/发卡分离，授信提额转模拟审核 |
| 理财 | 版本化五题测评、虚构产品筛选对比、红级申购/赎回、批次持仓与锁定期、T+1 演示工作日 09:00 结算 |
| 共用控制 | 10 分钟确认、3 分钟操作绑定模拟验证、执行时再核验、幂等、SQLite 事务和审计；预留资金不可挪用；共享业务时钟、模型用量与预算限制 |

本次完成路线图编号 **F01–F09、X01–X09** 的原型实现，并补入周期/批量转账、完整模拟卡申请流程、分类修正与预算。F08 的联网验收曾返回 HTTP 401，三条样本由规则降级处理；依用户选择保持离线，**不把这些样本计为真实模型成功**。

AA 多人垫付结算目前只做服务端计算预览，不保存结算单、不发起实际转账。仍未实现小票 OCR、外部自动催收、真实 IM 平台接入、真实身份验证和银行清算；不得宣传为已完成的线上能力。

## 快速启动（Windows）

要求 Python 3.11+、uv、Node.js 20.19+（或 22.12+）、npm。仓库包含 Python 与 npm 锁文件。

```powershell
# 仓库根目录：构建前端、安装后端依赖并启动本地单端口演示
.\scripts\run-demo.ps1
```

脚本仅在 `.env` 不存在时复制 `.env.example`，不会覆盖已有密钥。默认打开 `http://127.0.0.1:8000`；端口已占用时可用 `-Port 8001`。脚本不修改系统执行策略；若本机策略不允许脚本，可按下面命令逐步运行。

```powershell
cd frontend
npm ci
npm run build
cd ../backend
uv sync --frozen
uv run --frozen --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端构建产物由 FastAPI 在 API 路由后提供；只公开 `frontend/dist`，不公开项目根目录、数据库或配置。`/docs` 提供自动生成的 API 文档。首次启动创建 `data/veralane.sqlite3`，重启保留全部记录。

### 开发模式

```powershell
# 终端一
cd backend
uv sync --frozen --extra test
uv run --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
# 终端二
cd frontend
npm ci
npm run dev
```

浏览器访问 Vite 显示的地址（默认 `http://127.0.0.1:5173`）。`/api` 代理到 8000。页面使用哈希路由，支持刷新与前进/后退：`#/chat`、`#/transfer`、`#/bills`、`#/subscriptions`、`#/tasks`、`#/cards`、`#/investments`。

## 配置与数据

| 配置 | 含义 |
| --- | --- |
| `VERALANE_MODEL_MODE=offline` | 即使配置密钥也不发送模型请求；设为 `auto` 并重启后启用适配器 |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | 仅在本机 `.env` 设置，不提交仓库；鉴权失败等情况回退规则 |
| `DEEPSEEK_MAX_CALLS` / `DEEPSEEK_MAX_TOTAL_TOKENS` | 持久化调用/令牌上限，失败与不确定请求保守计入 |
| `DEEPSEEK_BUDGET_YUAN` | 配置价格下的估算上限；不是平台账户余额，也不含启用本地账本前的消费 |
| `DEEPSEEK_INPUT_PRICE_PER_MILLION_YUAN` / `DEEPSEEK_OUTPUT_PRICE_PER_MILLION_YUAN` | 两项须配齐才估价；未配不显示零成本。已有未定价历史时补价格会阻止继续调用，避免低估 |
| `VERALANE_DEMO_CONTROLS=0` | 关闭模拟验证码、模拟付款、时间推进、模拟审批/发卡等演示入口；不等于生产安全模式 |
| `VERALANE_DB_PATH` | 可选择独立 SQLite 路径，用于新演示；原数据库不会自动删除 |

原型使用一个共享虚构账户。会话 ID 只隔离任务入口，不是登录认证。请保持服务监听回环地址，不能直接作为公网银行服务发布。

初始业务日期为 `2026-09-30 09:00 +08:00`。业务时钟不会随电脑时间自然流逝；在任务中心“资金预留与时钟”或预约面板显式推进。所有会话共用时钟，推进会处理全局最早到期事件；授权有效期仍按实际 UTC 计算。

如需重新演示，先停止服务，备份数据并将 `VERALANE_DB_PATH` 指向一个新的文件。不要为了演示成功自动清空旧流水。扩展历史样本在 `backend/app/history_fixture.py`，只作为显式测试夹具，不自动混入现有演示余额。

## 关键演示流程

1. 账单页问“上个月餐饮花了多少”，打开对应交易；切换图表并导出。
2. 任务中心输入“下个月少花300元”，核对账单与协议，选择一项、确认取消；展示目标不足的真实差额。
3. 给“王明”转账展示消歧；给明确联系人生成 1200 元计划，完成模拟强验证，再单独确认。
4. 卡片页锁定尾号 6018，打开模拟刷卡测试，验证后端阻止付款；解锁后恢复正常检查。
5. 完成虚构测评，申购稳享 100 元；赎回后看到“待到账”，推进到下一结算事件才增加可用现金。
6. 建立生日任务，选择虚构商品与配送信息，确认预留；推进到下单、送达节点。任务取消与订单退款分别演示。
7. 转账页“周期 / 批量”核对具体日期或逐笔金额，观察每期状态及部分失败回执；AA 仅在模拟回款后入账。
