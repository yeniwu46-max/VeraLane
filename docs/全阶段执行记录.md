# 全阶段执行记录

项目：VeraLane / AI Banking | 更新：2026-10-05 | 分支：`codex/complete-banking-roadmap`

## 总体状态

已完成本机离线演示原型及技术交付文档，当前源码已同步到私有 GitHub 仓库 `https://github.com/yeniwu46-max/VeraLane`。当前版本覆盖路线图中的 F01–F09 与 X01–X09 原型能力，不能视为已接入真实银行的生产系统。

## 功能阶段

- **F01–F03 账单与订阅洞察：完成。** 账单问答、期间对比、异常线索、可追溯交易、订阅扣费识别与取消确认；自然语言聊天中的类别变化问题返回确定性报告及交易证据并记审计，分类纠正可按唯一交易证据生成黄级确认计划，歧义时先列出候选；账单可用柱状、环图和趋势图展示，并支持 CSV、JSON、打印/PDF；跨年分析样本提供单独的显式导入命令，追加前需停服备份，导入不改余额且具幂等性。
- **F04–F05 支出优化与偏好：完成。** 创建有版本的优化计划、提出订阅取消建议、展示预期节省金额和执行后差额；账单比较基期缺失时明确提示无法解释变化，存在历史样本时展示变化金额、分类贡献与证据；分类偏好可用于后续归类。聊天支持明确口述本月分类/总预算并生成黄级确认计划，已有分类预算沿用版本化修改流程，歧义范围不猜；可查询本会话已确认预算的剩余/超额及流水证据，并自然语言查询未来 30 天已授权转账和已知代扣估算。查询只读且保留未完成转账上下文。
- **F06–F07 交易确认和操作控制：完成。** 规则解析、账户数据复核、执行前确认、强验证挑战、幂等操作结果与审计记录；验证码只用于演示。
- **本地响应与业务分级加固：完成。** 最外层 ASGI 包装器为正常、404 与框架生成的 500 响应统一添加 CSP、内容嗅探/嵌入限制、Referrer 与 Permissions Policy；仅 HTTPS 请求添加 HSTS。带浏览器 Origin 的写请求还经过服务端回环来源校验，拦截跨站写入及外站 Host 重绑定；该检查不替代身份认证。金额型红级阈值收口到一个共用整数分规则，避免场景间硬编码漂移。OCR 上传路由在 multipart 解析前限制整个请求体，防止超限文件被先暂存到临时文件。
- **本机启动资源边界：完成。** 演示脚本将 BLAS 线程设为 1 以避免高核数环境下 OCR/NumPy 启动时过量分配；可通过参数手动提高，范围 1–16。
- **F08 模型成本与降级：完成。** 模型调用预算、次数/令牌上限与离线规则降级已实现。DeepSeek 试调用样本 3/3 返回 HTTP 401；用户选择保留离线演示，因此默认未设置模式时也保持离线，只有显式 `VERALANE_MODEL_MODE=auto` 才允许外发模型请求；不把失败样本描述为模型能力验证。
- **F09 自然语言转账：完成。** 支持“转给”“给联系人付款”“向联系人支付”“把金额付给联系人”“打款给联系人”等表达，从一句话提取对象、金额和备注，按姓名/手机号匹配并处理同名选择、重复付款提示及确认后模拟入账；明确拒绝/取消时会原子清除未确认草稿、撤销挑战并失效待确认 action，已确认预约仍需在预约管理中另行取消。“提醒我转账/不要忘记转账/转账后提醒我核对回执”等表达会被识别为提醒请求，不生成转账，且保留已有草稿与待确认操作；“如何给林悦转账”不会建计划，“怎么取消转账”不会取消现有授权；目前不支持实际创建或发送转账提醒。显式转账历史/状态问题走只读本地流水查询，避免被误解为新转账意图；返回流水证据并写审计，不创建 action 或改余额。代扣取消流程咨询同样只解释操作步骤，不新建或撤销取消计划。
- **X01 联系人别名与重复付款：完成。** 别名解析及近似重复交易提示。
- **X02 卡片操作：完成。** 卡片锁定/解锁、限额及线上交易限制等演示操作；支付模拟会检查卡片状态。
- **X03 资金预留：完成。** 可查看余额、可用余额和预留金额，并为任务预算保留演示资金。
- **X04–X05 生命周期任务：完成。** 生日任务收集预算、收件人与商品信息，先建立预留与定时计划，到期再经过业务检查；当前不连接真实商户或配送服务。
- **X06–X09 理财：完成。** 风险问卷、风险等级与产品匹配、产品比较、模拟申购/赎回以及强验证和持仓记录。
- **周期/批量转账和 AA：已有原型。** 当前提供定期转账、批量草稿和 AA 收款工作流；AA 支持均分、显式逐人份数/比例/百分比预填、手动份额、按菜品手工或本机 OCR 草稿拆分，服务端按整数分重算并保留明细；百分比合计不为 100%、同名或漏人时不猜。提供分次回款、逐笔回执、幂等重试、三演示日后的站内提醒，以及按原到账流水做授权模拟退款。OCR 图片仅在本机内存处理，识别结果需人工修订，不能自动建单。退款生成新的出账流水，保留原回款并调整净回款口径；不自动重开应收。提醒在 AA 页面可查看、跳转单据并标记已读，不发送消息。多人垫付可保存净额结算计划；本人相关的每笔转入/转出单独授权并更新模拟账本，其他参与者之间的路径仅作线下建议，不代表已付款。外部自动催收和金融机构对接不在本次原型范围内。
