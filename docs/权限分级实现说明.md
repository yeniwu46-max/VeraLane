# VeraLane 权限分级实现说明

版本：参赛原型交付稿 | 日期：2026-10-04

本文说明后端如何决定每项业务操作的权限级别，以及授权后如何复核和执行。所有金额阈值、状态和强验证均为虚构数据上的竞赛演示规则，不构成银行监管标准或真实身份认证。总体风险、威胁场景与已知风险见[安全自评与权限分级](安全自评与权限分级.md)。

## 1. 分级原则

权限级别只由后端业务工具根据固定操作类型、整数分金额和业务状态生成；模型只提取意图，前端只展示授权内容，二者都不能自行指定权限级别。涉及金额的“超过 ¥1,000”均为严格大于：刚好 ¥1,000.00 可保持黄级，¥1,000.01 起进入红级条件。

| 操作 | 黄级条件 | 红级条件 | 执行时复核 |
| --- | --- | --- | --- |
| 即时转账、批量转账 | 当日“转账 + AA结算”累计加本次金额不超过 ¥1,000.00 | 预计当日累计超过 ¥1,000.00 | 确认时重读当日累计与联系人；累计在准备后上升时，黄级授权会被拒绝，须重新生成红级计划并强验证 |
| 单次预约转账 | 单笔金额不超过 ¥1,000.00 | 单笔金额超过 ¥1,000.00 | 超 ¥1,000 的预约当前会被标红并提示不支持高风险预约，不可绕过强验证执行；到期重检对象、时窗、余额与累计限额 |
| 周期转账 / 生日任务 | 周期授权总额或生日订单总额不超过 ¥1,000.00 | 对应总额超过 ¥1,000.00 | 执行时比对授权快照、预留与当前状态；错过窗口不补扣 |
| AA 退款 / 本人付款的 AA 结算逐笔 | 退款单笔金额或本人当日累计转出不超过 ¥1,000.00 | 退款金额或本人当日累计转出超过 ¥1,000.00 | 重读原回款、可退金额、联系人和当日累计；本人收款记模拟收入，不套用转出阈值 |
| 模拟刷卡支付 | 单笔金额不超过 ¥1,000.00 | 单笔金额超过 ¥1,000.00 | 执行时核对卡状态、线上开关、支付渠道、单日限额、版本和可用余额 |
| 卡片挂失、信用额度申请、办卡申请 | 不适用 | 始终红级 | 挂失、申请、审批和发卡分别建状态；红级确认只提交模拟申请，不意味着审批通过 |
| 理财申购 / 赎回 | 不适用 | 始终红级 | 强验证后再确认；复核适当性、产品/持仓版本、可用资金/份额和费用 |
| 其他低影响设置 | 显式展示并确认后可黄级，例如锁卡、线上开关、调低限额、取消模拟代扣、预算与分类修改 | 若业务规则规定高风险则转红级；越权或状态冲突直接拒绝 | 检查当前状态、版本及本次授权 payload，失败不变更账本 |

## 2. 操作状态与红级挑战

```text
意图/表单输入
    ↓ 后端校验联系人、金额、限额、业务状态并冻结参数快照
pending action（黄级 / 红级）
    ├─ 黄级：用户核对具体影响并确认
    └─ 红级：签发 3 分钟挑战 → 校验通过 → 用户仍需单独确认
    ↓ 执行前重读 action、会话、状态、到期时间、payload hash 与业务快照
同一 SQLite 写事务执行 → 账本/业务状态/审计记录 → 可重放的原始回执
```

红级挑战绑定 action ID、session ID 和 payload hash；验证码只存带挑战 ID 的摘要。每个挑战最多校验三次，连续失败会锁定；重新签发撤销旧挑战。action 过期、payload 变化、会话不匹配、联系人/产品/计划版本变化或当前余额不足都会拒绝执行。通过挑战并不等于自动执行，用户仍须逐项确认。

演示页面会直接显示 `demo_code`，所以这只验证授权状态机，不具备短信、硬件 MFA 或抗账号接管能力。所有余额、交易、联系人、卡片、产品和验证码均为模拟数据。

## 3. 代码与验收证据

| 控制点 | 实现位置 | 关键检查 |
| --- | --- | --- |
| action 创建与确认 | `backend/app/service.py`、`backend/app/execution_controls.py` | action 类型/会话/tier/快照/过期状态；红级须先有有效挑战 |
| 资金预留和出账 | `backend/app/execution_controls.py` | 以整数分校验可用余额；事务内统一扣款/预留/释放 |
| 转账与日累计限额 | `backend/app/service.py`、`backend/app/recurring.py` | 即时转账、批量、周期计划及到期执行重新核对累计金额 |
| AA 退款与净额结算 | `backend/app/aa.py`、`backend/app/aa_settlement.py` | 原到账流水、联系人、可退款额和逐笔本人转出累计复核 |
| 卡片及理财 | `backend/app/cards.py`、`backend/app/investments.py` | 挂失/申请/投资固定红级；卡片/产品/持仓版本执行时核对 |
| 生日预算 | `backend/app/life_tasks.py` | 总订单超过阈值升级红级；确认后先预留，价格和任务快照变化则拒绝 |
| 回归测试 | `backend/tests/test_workflows.py`、`test_controls.py`、`test_recurring.py`、`test_aa_settlement.py`、`test_cards.py`、`test_investments.py`、`test_life_tasks.py` | 覆盖阈值边界、挑战重放/过期/错误次数、日累计升级和执行时复核 |

复现完整测试与前端检查：在仓库根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`。测试通过只说明当前模拟规则符合断言，不等于第三方安全审计或真实模型准确率。
