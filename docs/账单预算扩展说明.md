# B01 / B02：账单归类与月度预算扩展

## 设计范围

- **B01 用户纠正分类**：用户可在账单页选择支出，或在聊天中说明流水编号、商户/金额，或引用最近一条只含单笔交易的账单结果，再说明新分类和原因。先展示旧分类、新分类与交易摘要，确认后保存覆盖记录。命中多笔时提供候选清单供选择；无证据或范围不唯一时不创建计划。交易表的金额、原始分类、交易对象、时间、备注均不修改。
- **B02 月度预算**：用户可在预算页或聊天中明确设置当前演示月份、唯一消费分类（或全部支出）及金额，经黄级确认后保存。聊天遇到多分类歧义、未覆盖分类或非当前月份时不猜、不创建计划；已有同分类预算时生成带当前版本的修改计划。预算支持修改和删除；预算变更不冻结或划转资金。
- 所有记录与权限均属于现有本地模拟模型，不构成实际金融建议。

## 分类数据与授权

`bill_category_overrides` 保存交易原始分类、有效分类、用户理由、版本及最近确认动作；`bill_category_history` 追加每次修改历史。有效分类供账单汇总、洞察分类比较和预算计算使用。银行业务规则继续使用不可变的原始流水字段，例如转账日限额与代扣证据不能被用户重新归类绕过。

同一模拟账户的有效分类跨会话用于只读报告；后续编辑权限绑定最近一次修改所属会话。现有系统没有真实登录，不把此会话约束宣称为生产身份认证。修改时冻结交易摘要和覆盖版本，确认时重检，旧版本不可覆盖后续修改。

共享接入点：`apply_effective_categories(conn, rows)` 返回含有效 `category`、`original_category`、`classification_reason`、`classification_version` 的字典列表。现有 `insights._read_transactions` 和 `service.bill_summary` 在读出支出记录后调用它；之后原有汇总、图表、导出继续复用。

## 预算与未来资金口径

预算支出仅累加当前月已发生的支出流水，按有效分类筛选。预算剩余可以为负；显示超额金额，不能将负数隐藏为零。AA 待收款、未到账赎回款均不抵减已发生支出。

未来 30 天分别列出：

1. 当前账面余额与有效预留；当前可用余额已扣除预留，后续不能再次扣减同一笔预留。
2. 已经确认且仍待执行的单次预约与有限周期转账；逐期核对父授权、金额及日期快照，只纳入未来 30 天窗口内的期次，未确认、已取消和已错过窗口的操作不计入。
3. 已保存生效协议的下一扣费记录，标为已知代扣估计，不称为本次新授权，也不计入已确认预约转账。
4. 尚待结算的理财赎回，单列说明，不作为当前可花现金。

场景估计：`预约后可用金额 = 当前可用余额 − 未来 30 天已确认预约金额`；另列 `若已知代扣也发生的可用金额 = 预约后可用金额 − 已知代扣金额`。这两项不是保证余额。生日订单已经由预留覆盖时，不再重复扣减预计订单金额。已发生支出已反映在账面余额，不能在预测中再减一次。

固定数据可能不完整，未知消费、未来收入、协议变化和任务失败均会改变结果。无法从流水推断使用频率或真实消费意图。

## API 合同

- `GET /api/bill-preferences?session_id=...&period=本月`：返回可编辑交易、分类历史、预算及未来资金口径。
- `POST /api/bill-preferences/classifications/prepare`：`{session_id,transaction_id,category,reason}`，生成 `bill_classification` 黄级确认。
- `POST /api/bill-preferences/budgets/prepare`：`{session_id,month,category:null|string,amount_yuan,budget_id?:string}`，生成 `bill_budget_upsert` 黄级确认。
- `/api/chat` 支持“本月餐饮预算控制在 1500 元”“本月总预算调整为 3000 元”等明确表达；通过同一预算服务创建同类型确认动作，不另设写入路径。
- `/api/chat` 支持“本月餐饮预算还剩多少”等只读查询，返回当前月份额、已支出、剩余/超额及对应流水编号；没有已确认预算时明确提示，不会把待确认草稿当成已保存预算。查询会话只读取该会话预算，并保留未完成的转账草稿。
- `/api/chat` 支持未来 30 天现金流查询，逐项列出已授权预约转账与已登记协议的扣款估算，并返回预测口径及限制。代扣估算不等同扣款授权，AA 待收款和未到账赎回不计入可用现金。
- `/api/chat` 支持“把交易 tx-8 归类为差旅，因为是出差打车”“这笔是差旅，不是交通”等表达；交易引用必须唯一解析为当前账户已发生的支出，再通过同一分类覆盖服务创建 `bill_classification` 黄级确认。
- `POST /api/bill-preferences/budgets/{id}/delete/prepare`：生成 `bill_budget_delete` 黄级确认。
- `POST /api/bill-preferences/actions/{id}/discard`：放弃当前未确认编辑，服务端使旧确认失效。

版本冲突、跨会话编辑、原始交易发生变化均拒绝执行。删除预算不会修改流水、退款或改变余额。所有金额以整数分计算。
