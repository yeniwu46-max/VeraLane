# 周期与批量转账：实现边界与授权规格

本模块使用虚构账户与已验证联系人，不连接真实银行。所有计划先预览，再明确确认；总计划金额超过 ¥1000 时需要绑定当前计划的模拟强验证。

## 周期转账

- 用户明确填写首个完整日期与时间、每月日号、单笔金额、联系人及次数（1–12 次）。首日必须与每月日号一致，首个时间必须晚于当前业务时钟。
- 按首日的北京时间逐月展开；某月没有指定日号则跳过该月，不提前到月末、不顺延到下月第一天。次数指实际执行日期数量；界面同时显示跳过月份、全部实际日期、单笔金额与总授权金额。
- 全部日期、联系人指纹、金额、备注及每期 10 分钟执行窗口绑定授权。确认不会预留余额；每期到期重新检查可用余额、联系人和当日累计权限。
- 每期只能执行一次。余额不足、联系人变化或超窗口，当前期记录失败或过期，不补扣、不无限重试；其他已明确授权的未来期次保持原日期。可取消全部剩余未执行期次，已执行款项不退款。
- 总金额超过 ¥1000 的红级长期计划须在创建时完成模拟强验证；之后具体未来日期属于该次持久授权，不要求验证码一直有效。黄色计划执行时若当日累计已超过 ¥1000，则失败并要求另行授权。

## 批量转账

- 一次选择 2–10 位不同的已验证联系人，每行都有独立金额和备注。拒绝同一计划的重复联系人，避免界面误加同一人。
- 计划展示逐行信息与总金额；已完成确认后，按照预览顺序逐行执行。每行使用稳定子操作编号和独立数据库保存点。
- 业务失败只记录该行原因，其他行继续；显示全部成功、部分成功或全部失败的真实结果。重复确认返回原批次结果，不重扣已成功行。
- 技术故障使整次未提交的数据库事务回滚，保留原待确认状态；重试通过唯一子操作键避免重复记账。
- 批次总金额超过 ¥1000，或者生成计划时当日累计加本批次超过 ¥1000，需模拟强验证。黄色计划执行时累计限额仍重检，不因批量入口绕过。

## 共同安全约束

- 普通转账、周期期次、批量子项共用可用余额与转账执行器；父授权只能用于自己列出的子操作、金额、对象和备注。
- 模拟强验证展示演示验证码，说明操作绑定、期限和失败次数，不构成真实身份验证。
- 后端保留完整回执、授权快照和审计；草稿修改需重新生成授权。模块不自动创建无限周期，不在失败后补扣，不将取消未来任务称为退款。
