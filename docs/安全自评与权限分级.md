# VeraLane 安全自评与权限分级

日期：2026-10-09 | 范围：仓库当前竞赛原型及 `demo.wuyeni.cn` 受口令保护的云端演示入口 | 评估类型：实现证据自评，不是独立渗透测试、银行合规审计或生产认证。

## 1. 安全结论

VeraLane 的设计目标是让虚构账户内的可见操作可核对、可授权、可回放。金额处理、计划快照、有限工具和 SQLite 原子提交都有后端约束，并由专项测试覆盖。当前云端竞赛演示入口为 `https://demo.wuyeni.cn`：Nginx 在公网终止 TLS，并对页面和 API 使用单一共享的 HTTP Basic Auth；应用容器只绑定服务器回环地址 `127.0.0.1:8000`。未登录请求已验证返回 HTTP 401，HTTP 访问会跳转 HTTPS。

这层 Basic Auth 只是一道共享口令门禁，应用没有真实用户身份认证、账户隔离、MFA 或每用户授权审计；`session_id` 可由客户端提供，演示验证码会直接展示，所有演示数据共用虚构账户。域名可从公网访问，因此入口仍有互联网攻击面。该部署仅用于受控竞赛演示，不得连接真实账户、输入真实个人资料或用于真实资金操作。服务器容器默认离线模式，`DEEPSEEK_API_KEY` 为空；登录口令只配置在服务器 Nginx 文件中，不写入仓库、文档或源码压缩包。

默认模型模式为 `offline`。早期联网样本 3/3 收到 HTTP 401；2026-10-05 隔离评测中前两次合成请求也返回 401，第三次成功解析为转账意图、金额为 300 元，但终端中文输出乱码，收款人和备注精确匹配未核实。单个成功样本不足以估计准确率。当前云端没有配置模型密钥，不会向模型服务发送请求。20 元预算为本地估算控制，不代表供应商账户余额，也不包含启用本地记录前的调用。

## 当前云端演示部署

- **入口和链路：**`demo.wuyeni.cn` 的 80 端口只负责跳转 HTTPS；443 端口由 Nginx 终止 TLS，并在转发页面和 API 前统一执行 HTTP Basic Auth。后端只监听 `127.0.0.1:8000`，由 systemd 管理容器进程。TLS 证书由 ACME 自动续期；Nginx 有证书续期后的 reload hook。
- **访问凭据：**全体演示者共用一个口令，没有单独用户、角色、撤权记录或 MFA。口令哈希位于服务器 `/etc/nginx/.veralane-demo.htpasswd`，不在代码仓库或交付压缩包中；评委访问凭据应通过比赛平台或其他受控渠道单独提供。
- **数据和模型：**服务器使用独立 SQLite 演示库；联系人、余额、交易、产品、卡片和验证码均为虚构数据。容器明确设置 `VERALANE_MODEL_MODE=offline`，模型 API 密钥为空。
- **已验证项：**Nginx HTTPS 证书校验成功、HTTP 跳转 HTTPS、未认证 HTTPS 请求返回 401、容器健康接口返回 `{"status":"ok"}`，应用端口只监听 loopback。
- **剩余风险：**共享口令泄露会暴露所有演示会话；没有应用级身份认证/MFA/按用户隔离，无法审计具体访问者；公网入口仍可能遭受口令猜测和拒绝服务；尚未验证云主机备份恢复、入侵检测和灾备；部署未经过独立渗透测试或生产合规审查。

## 2. 权限分级矩阵

| 级别 | 原型操作 | 执行条件 | 说明 |
| --- | --- | --- | --- |
| 查询 | 余额、账单、交易证据、协议、产品、卡片、任务 | 限制在虚构账户；部分数据按 session 过滤 | 查询不改变银行状态 |
| 草稿 | 账单计划、生日草稿、卡片操作、理财计划、周期/批量转账 | 解析不等于授权；缺失字段留空并追问 | 自然语句只映射固定工具 |
| 黄级确认 | 小额转账、代扣取消、别名修改、预算/分类、资金预留、卡片锁定/线上开关、有限批量计划等 | 展示对象/金额/影响，用户复核并确认；执行时重检 | 具体 tier 由 action 与金额规则确定 |
| 红级挑战 + 确认 | 高额/日累计转账、挂失、卡申请或模拟授信申请、理财申购/赎回、超额生日下单 | 当前 operation/session/payload 绑定 3 分钟模拟挑战，并单独勾选确认 | 挑战码向演示页面展示，绝不是真实身份认证 |
| 定时授权 | 单次预约、有限周期转账、生日计划、赎回结算 | 冻结特定收款人/商品/金额/日期/次数/窗口；每次到期再校验；超窗不补扣 | 手动推进前有说明，推进可能运行所有者范围内已授权事件 |
| 明确拒绝/停止 | 挂失卡普通解锁、过期/篡改 action、错误会话、价格或状态快照变化、窗口已过 | 重新核对并生成新的计划 | 不因模型说“已完成”绕开业务工具 |

卡片意图还有一层动作选择保护：仅表达“找不到/丢了/遗失/不见了”时，解释器只返回澄清与临时锁卡、正式挂失两个选项，不生成待执行 action。正式挂失选项继续经过红级模拟挑战和显式确认；挑战码直接显示在演示界面，只证明流程绑定，不是真实身份认证。

权限级别由后端业务工具按操作类型和整数分阈值生成，不由模型或前端请求指定。阈值、强验证状态机、执行复核及源码证据见[权限分级实现说明](权限分级实现说明.md)。

周期转账最多 12 期；每期窗口 10 分钟，不会为错过/余额不足而自动补扣。批量结果逐项列出，失败不回滚已成功的独立业务项。预留支出先消费自己的预留，再写对应流水；一般支出只从可用余额扣除。AA 均分、比例和手动份额都由服务端按整数分计算并复核授权快照；建单本身不扣付款人余额，模拟到账才增加入账交易。

## 3. 安全控制与证据

| 控制 | 实现证据 | 限制 |
| --- | --- | --- |
| 模型不直接执行 | `agent.py` 仅解析受限 Intent；`service.py` 路由固定 action 到 Python 工具 | 离线解析覆盖有限，无法保证所有口语表达正确 |
| 转账明确拒绝、提醒与教程隔离 | `service.py` 在意图解析前识别常见否定/取消表达；原子清除未完成草稿、失效待确认 action 并撤销挑战；单日期提醒写入会话隔离表，到期只更新提醒状态，不创建金融 action 或触碰账本；提醒不会清除或覆盖已有草稿/action；“如何转账”不新建操作，“怎么取消转账”不会撤销已有操作；确认后的预约必须显式去预约管理撤销 | 日期解释仍由有限规则覆盖；只支持一个明确日历日，无系统推送、精确时刻或重复计划；转账对象和金额仅作为用户文本展示，不据此发起操作 |
| 订阅取消明确拒绝、延后与教程隔离 | `service.py` 在意图解析前识别“先别取消”和“下次扣款后再取消”；前者失效当前会话未确认单项/批量 action，后者要求澄清；“怎么取消订阅”只说明流程，不新建或撤销 action | 词法规则覆盖有限；延迟/条件取消没有执行器，只能明确告知未执行；订阅取消提醒不创建，现有续费提醒只提示核对模拟协议 |
| 预算教程隔离 | “怎么设置本月餐饮预算1500元”返回流程说明；不生成或覆盖预算 action，明确控制语句仍走版本化预览和确认 | 基于词法提示词；需持续覆盖新口语表达 |
| 分类教程隔离 | “怎么把交易 tx-8 归类为差旅”返回流程说明；不生成或覆盖分类 action，明确的交易归类指令仍走原确认流程 | 基于词法提示词；需持续覆盖新口语表达 |
| 卡片咨询与明确拒绝隔离 | “怎么挂失6018卡”“不要挂失6018卡”“不要关闭线上支付”等在建计划前被识别；不会创建或覆盖卡片操作 action；正式挂失仍须红级模拟挑战和独立确认 | 基于有限词法提示词；复杂的同时否定与肯定表达会保守要求用户重新明确 |
| 红级金额边界 | `execution_controls.py` 的 `requires_red_tier()` 统一提供严格大于 ¥1,000 的比较；即时/周期/批量转账、卡支付、AA、生日任务共用 | 固定阈值仅为虚构演示规则；新业务必须调用共享规则并补场景测试 |
| 授权快照 | action 保存 payload JSON、tier、会话和过期时间；`require_verified` 重读数据库 action 并比对 payload hash | session 不是登录凭据，单机用户可访问整个数据库 |
| 模拟强验证 | `execution_controls.py` 挑战绑定 action/session/hash；3 分钟、至多 3 次错误、重新生成废弃旧挑战 | challenge 码直接暴露；不要称作 OTP、短信验证或生产强认证 |
| 余额与预留 | `available_cents = ledger balance - active reservation remaining`；各出账路径使用共同 `debit/consume` 校验 | 所有模块/新支付入口必须持续纳入统一工具；独立外接模块未经审查可能遗漏 |
| 原子与幂等 | 资金执行使用 `BEGIN IMMEDIATE`；多人结算计划/逐笔授权与显式提醒刷新在写事务中完成；提醒列表和概览 GET 只读，模型预算以 `query_only` 快照计算；30 个金融 GET 路由经前后 SQLite 全表及 schema version 快照测试；交易唯一 ID、action result 重放、退款/结算状态检查 | SQLite 单写者和本机文件不提供分布式并发/灾备 |
| 输入、导出 | Pydantic 长度/枚举/extra-forbid 验证，Decimal 金额，CSV 对公式前缀转义 | 仍需持续对所有 API 做边界审计 |
| 事件调度 | `jobs.py` 全局排序，演示时钟推进最早事件；UTC TTL 与业务时钟分开 | 进程关闭期间不会后台执行；恢复后超过窗口即失败/过期 |
| 离线回退与预算 | offline 模式挡住请求；call/token/inflight/timeout 预算账本 | 提供商原有支出未知；单价缺失时无费用估值；模型真实质量未验收 |
| 静态文件边界 | 构建后只挂载 `frontend/dist`，API 路由优先；应用只监听 loopback；公网 Nginx 对页面和 API 统一启用 TLS 与共享 Basic Auth | Basic Auth 不是应用登录；缺少多用户隔离、MFA、按用户审计和抗暴力猜测控制；主机、浏览器与公网可用性仍需单独防护 |
| 本机 Host 与浏览器写请求来源 | `TrustedHostMiddleware` 限制所有请求的 Host 为 localhost/回环 IP；`BrowserWriteOriginMiddleware` 拒绝外站 Origin 的 POST/PUT/PATCH/DELETE；开发前端仅允许 CORS 中列出的两个回环来源 | 只缓解 DNS 重绑定和浏览器跨站写请求，不认证用户；本机命令行调用与其他本机程序仍不受此边界保护 |
| 浏览器安全响应头 | `main.py` 的最外层 ASGI 包装器为正常、404 和框架生成的 500 响应添加 CSP、nosniff、DENY frame、Referrer/Permissions Policy；HTTPS 响应添加 HSTS；云端 Nginx 也添加 HSTS | CSP 为动态图表和可调面板保留 inline style；本机默认 HTTP 没有 TLS，云端 TLS 仅保护传输，不提供应用级身份认证 |

## 4. 威胁场景与应对

- **模型/流水文本提示注入及转账意图撤回：**备注、商户、用户描述均视为数据；Intent 解析 schema 有限，确认/执行权限由工具层决定。明确的转账否定/取消会在意图解析前清除未确认草稿、失效 action 并撤销挑战；单日期提醒表达只保存站内核对事项，绝不创建或执行转账，并保留已有草稿和待确认 action；已确认预约仍须单独撤销。日期规则不能覆盖所有口语变体，用户应检查对象和金额。
- **旧计划被修改后执行：**计划修改增加版本并使 action 失效；执行时核对原 payload、版本、收款人 fingerprint、卡版本、产品版本/净值、预算和时窗。
- **并发重复扣款：**事务锁和唯一交易键防止双写；失败时同事务回滚资金及执行状态。端到端网络超时后客户端应读取原 action 结果。
- **多人 AA 结算错付或冒充完成：**确认时保存带联系人指纹的不可变计划，执行时重算并逐笔授权；本人转出复核可用余额和日累计强验证边界。仅本人账户相关路径会写本地账本，其他成员间的建议不能在本机执行或标为完成。
- **AA 回款误退款/超额退款：**退款授权绑定指定已到账交易、收款请求及当前可退额；执行时重查原付款人和可用余额，并在同一 SQLite 写事务中记退款支出、退款记录和审计。部分退款不改变原回款，重复确认复用原回执；退款不通知付款人，也不代表真实款项已退回。
- **把预留资金花掉：**全体实现中的转账、卡模拟支付、理财申购、生日订单通过共同可用余额/预留 helper；若未来新增收款/支付工具须纳入本检查。
- **取消、退款或计划误报：**银行代扣取消不声称退订商户；任务取消不等价于订单退款；AA 建单不记收入；赎回未到期不可计现金。
- **演示时钟推进误触：**全局事件页列出事项，推进须显式复核；可能执行已授权操作，不能在不知情情况下自动快进。
- **单机资料泄露：**SQLite 和 `.env` 是本地文件；仓库忽略 `.env`、数据库和日志，前端静态挂载不包含数据目录。操作系统账号与磁盘权限仍需由运行者保护。

## 5. 已知风险 / 未完成

1. **无账户登录、真实会话认证或多租户隔离。**session id 是浏览器随机值但服务器信任传入值；客户端伪造会话可访问同一虚构账户中的一部分会话任务。上线真实金融数据前必须建立真实认证和授权模型。
2. **挑战码暴露。**UI 直接展示 demo_code，安全设计是为演示强制复核和 action 绑定，不提供抗账号接管能力。
3. **模型联网结果不足以验收效果。**早期本地 `.env` 配置遇到 HTTP 401；2026-10-05 的隔离评测中两条合成请求返回 HTTP 401，一条成功解析出转账意图和金额，但收款人、备注未核实。依用户选择保持默认离线；模型外呼只有明确配置 `VERALANE_MODEL_MODE=auto` 才允许，模式缺失或无效时均失败关闭。API key 不写入文档或仓库。更多在线评测需先获得用户授权并由真人配置新密钥。
4. **20 元预算是估算。**当前 DeepSeek 账户已有消费未知；价格未配置则显示未知而不是 0。调用上限只覆盖本应用启用账本后的请求。
5. **SQLite 单机运行。**无服务端加密密钥托管、备份轮转、高可用、远程审计或交易账务对账。
6. **虚构商户、卡和产品。**审批规则、卡支付和金融适当性不可类推到真实银行制度；推荐不是投资建议，固定净值不代表回报。
7. **定时任务依赖本机进程。**关闭期间不会实时执行；演示数据库持久但没有跨设备所有者管理。
8. **当前非功能范围：**真实银行/商户/IM 接入、真实短信/硬件 MFA、向联系人自动催收、生产安全监控和监管/法律评估。本机 OCR 可能漏识、误识或错读金额；识别只生成菜名/金额候选，不匹配真实付款、分配参与人或修改垫付总额，必须由用户对照原票逐项核验。OCR 路由在 multipart 解析前限制整个请求体，拒绝超限内容后才会创建临时上传对象；通过限制的图片只在本机内存处理，不传云端、不落盘。AA 未收款提醒只在本地站内出现，不发送消息或支付请求；AA 回款、退款和本人相关结算只在本机记模拟账；其他参与人间的结算仅保留建议，不保存其付款证明。
9. **本机演示不提供传输加密。**默认仅监听回环地址并添加浏览器安全响应头；HTTP 下不发 HSTS。若改为远程部署，必须在受信 TLS 终止层启用 HTTPS/HSTS，并重新审查 CSP、CORS、认证和网络暴露面。
10. **本机 Host/来源校验不是身份认证。**服务端限制 Host 为 localhost/回环地址，并校验带 Origin 的写请求来源；无 Origin 的非浏览器请求仍可访问。此控制不能替代登录、CSRF token、会话签名或资源所有权检查。
