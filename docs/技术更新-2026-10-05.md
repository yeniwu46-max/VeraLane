# VeraLane 技术更新记录 — 2026-10-05

## 今日更新

### SQLite 空闲调度扫描

- 后台任务扫描器每两秒轮询预约转账、理财结算、生日任务、周期转账和 AA 提醒。此前每次轮询都会直接开启 `BEGIN IMMEDIATE`，即使没有到期事件也会短暂占用 SQLite 唯一写入者位置。
- 扫描器现在先在只读事务中检查共享事件队列及演示业务时钟；没有到期事件就直接返回，不申请写锁。发现可能到期事件后，仍通过 `BEGIN IMMEDIATE` 获取写权，并在事务中重新检查和执行，保留并发场景下的原子性。
- 新增回归测试，断言空闲扫描不会打开写事务。预约转账原有到期执行、重复扫描和取消竞态测试继续覆盖写路径。

## 风险边界

- 只读预检与写事务之间存在并发窗口。如果另一个线程在预检后创建立即到期事件，该事件会由下一次轮询处理；获得写锁后的执行仍以数据库内当前事件和授权状态为准。
- 本修复降低空闲轮询对 SQLite 写锁的争用，并通过回归与重复运行验证；它不代表 SQLite 适合真实银行并发负载。生产系统应使用具备并发写入能力的事务数据库及独立任务队列。
- 所有业务和账户仍为本地虚构演示数据。
