# VeraLane 技术更新记录 — 2026-10-05

## 今日更新

### SQLite 空闲调度扫描

- 后台任务扫描器每两秒轮询预约转账、理财结算、生日任务、周期转账和 AA 提醒。此前每次轮询都会直接开启 `BEGIN IMMEDIATE`，即使没有到期事件也会短暂占用 SQLite 唯一写入者位置。
- 扫描器现在先在只读事务中检查共享事件队列及演示业务时钟；没有到期事件就直接返回，不申请写锁。发现可能到期事件后，仍通过 `BEGIN IMMEDIATE` 获取写权，并在事务中重新检查和执行，保留并发场景下的原子性。
- 新增回归测试，断言空闲扫描不会打开写事务。预约转账原有到期执行、重复扫描和取消竞态测试继续覆盖写路径。

### 浏览器写请求来源校验

- CORS 白名单之外，再由 ASGI 中间件在服务端拒绝带外站 `Origin` 的写请求，覆盖 POST、PUT、PATCH 和 DELETE。
- `TrustedHostMiddleware` 进一步限制所有请求的 Host 为 localhost 或回环 IP；外站 Host 即使请求只读接口也会在进入 API 前被拒绝，避免将 DNS 重绑定只防写入、不防读取。
- 运行时白名单不包含测试框架的 `testserver` 别名；测试客户端统一用真实本机回环地址，避免为了测试扩大生产允许的 Host。
- 接受本地开发 UI 的两个固定回环来源；生产构建页可使用 localhost 或回环 IP 的同源请求。无 `Origin` 的测试、命令行和服务端调用仍可访问 API。
- 测试覆盖外站 Origin、伪装成外站 Host 的 DNS rebinding 请求、本地同源请求及本地 Vite 开发来源。
- 此保护只限制浏览器来源，不提供登录、真实会话认证或 CSRF token；不改变单机虚构账户的身份边界。

### 自然语言转账表达扩展

- 离线意图解析新增“给林悦付款”“向林悦支付”“把金额付给林悦”“给林悦打款”等定向付款说法，并沿用联系人消歧、手机号匹配、金额核验和确认门槛。
- 历史问题“本月给林悦付了多少钱”按只读流水查询处理；新增支付否定可撤回未确认草稿，同时避免“不要给林悦付款提醒”误清业务草稿。
- 复核发现“不要忘记转给林悦100元”“提醒我明天给王明转100元”会被解析为当前转账。现在提醒表达在模型/规则意图解析前被拒绝，不生成或执行转账，并保留已有的未完成草稿和待确认操作；“转账后提醒我核对回执”与“转账提醒”管理也明确说明尚不支持，不会被误判成流水查询或模糊预约。
- 流程咨询“如何给林悦转账”不创建操作；“怎么取消转账”不撤销现有待确认授权，并解释正确的撤回/预约取消方式。自然语言流水状态问题继续优先使用只读查询路由。
- 代扣流程咨询“怎么取消云影会员自动续费”也不生成取消计划；“如何取消订阅”不会改动已有待确认操作。只有明确提出立即取消才会进入既有的逐项确认流程。
- 预算流程问句“怎么设置本月餐饮预算1500元”不会新建或覆盖预算变更授权；明确的控制语句仍生成待确认计划。
- 交易归类教程问句“怎么把交易 tx-8 归类为差旅”只返回步骤说明，不创建或覆盖分类修改计划；明确纠正指令保持原确认流程。
- 新增姓名/手机号/同名、备注隔离、历史查询只读、否定、提醒、预算及分类教程问句不执行/不覆盖草稿边界测试，包含换行分隔及转账后提醒语句。完整后端 **648 项通过**。

### 本地服务连接状态

- 浏览器实测发现后端离线时页面会提示断连，但服务恢复后不会主动更新状态，必须刷新页面。
- 增加 10 秒一次的本地健康检查；断连或核心账本不可读时状态提示变红，服务恢复后自动更新为就绪，并重新读取概览和联系人、清除残留的启动连接错误。健康接口只读确认模拟账户及核心表可用，不返回余额或流水明细，也不触发模型或外部 API。

### 确认授权到期边界

- 通用确认器先前仅在当前时间晚于 `expires_at` 时拒绝；在精确相等的边界瞬间仍会执行，与强验证器的“到期即失效”口径不一致。
- 现在将到期时刻本身视为过期，并在同一事务内标记操作过期、写审计记录；回归用例冻结时钟在精确到期时刻，断言返回 409、状态为 expired 且模拟账本交易数不变。
- 强验证挑战成功后，错误验证码重试此前会把状态改回 active 或锁定，从而撤销有效授权。现在成功态下错误重试只返回 409、不增加尝试数或改动授权；正确重试保持幂等，重新签发新挑战仍会撤销旧授权。

### 提醒列表 GET 只读

- 复核发现 `GET /api/reminders` 会在读取时创建续费与 AA 站内提醒，属于可观察的数据写入，也会让提醒首次出现取决于页面是否被打开。
- 新增显式 `POST /api/reminders/refresh` 执行幂等提醒生成；列表端点现在只查询和返回现有提醒。订阅页加载时先触发刷新，再并行读取诊断与提醒；AA 页继续只读加载，提醒可以由订阅页刷新或业务时钟任务创建。
- 回归断言初始 GET 不生成提醒、显式刷新新增两条、重复刷新新增零条、GET 重复读取结果一致，已读状态仍可持久化。
- 架构说明与安全自评已同步更新。

### 概览中的模型预算状态只读

- `GET /api/overview` 查询模型调用状态时此前会获取 `BEGIN IMMEDIATE` 写锁、按需建表，并将租约已过期的 `reserved` 调用落库为 `unknown`。
- 现在状态查询使用 SQLite `query_only` 只读快照；过期调用在返回视图中计为未知并释放活动并发槽，但保留其保守 token/费用占用。真正发起后续写操作时再持久化超时清理。数据库或用量表尚不存在时也返回零用量，不为 GET 创建文件/表。
- 新增单元和 HTTP 路由回归：状态 GET 对过期记录给出正确的未知状态、活动请求数为零，同时底层记录不变；初始离线查询不会创建账本或用量表。

## 风险边界

- 只读预检与写事务之间存在并发窗口。如果另一个线程在预检后创建立即到期事件，该事件会由下一次轮询处理；获得写锁后的执行仍以数据库内当前事件和授权状态为准。
- 本修复降低空闲轮询对 SQLite 写锁的争用，并通过回归与重复运行验证；它不代表 SQLite 适合真实银行并发负载。生产系统应使用具备并发写入能力的事务数据库及独立任务队列。
- 所有业务和账户仍为本地虚构演示数据。
